# 校验门细则

任何 OCR/抽取结果在交付前必须过校验门。校验不通过就重跑或换引擎，不把残缺结果交给用户。

校验工具：`scripts/verify_extract.py`

## 一、五项校验

### 1. 页数对账（最关键）
- **做法**：输出 Markdown 的分页节数（`## 第N页` 数量）vs 源 PDF 实际页数
- **通过判据**：输出节数 ≥ 源页数（允许因合并略多，不允许少）
- **不通过**：残缺，缺哪页重跑哪页（利用断点续跑）；整体残缺严重则换引擎

```bash
python3 scripts/verify_extract.py output.md --source input.pdf
```

### 2. 空页检测
- **做法**：逐页检查内容，空白页或只有占位符（`（本页无文字）`）的页标记出来
- **判断**：
  - 文档本身就有空白页（如章节分隔页）→ 正常，记录即可
  - 非预期空白页 → 可能 OCR 失败，检查该页图片是否清晰、是否纯图片（图表页无文字是正常的）
- **连续空白页**（≥3 页）必须告警，大概率是转图或 OCR 批量失败

### 3. 乱码 / 替换字符检测
- **替换字符 `�`**：出现即告警，通常是编码问题或字体缺失
- **异常高比例标点**：某页标点符号占比 >40% 可能是识别错乱
- **连续乱码字符**：非 CJK/非 ASCII 的异常字符序列
- **常见 OCR 错字**：用替换表后处理（见 engine-vision.md），但校验阶段要统计未修正的错字密度

### 4. 重复页检测
- **做法**：相邻页内容完全相同（去除分页标记后逐字比较）
- **判断**：
  - 文档本身有重复页（如模板页）→ 正常
  - 非预期重复 → 可能是 PDF 转图时页码错乱或 OCR 缓存串用，检查源 PDF
- `pdf_ocr.sh` 已在每处理一个新 PDF 前清空分页缓存，但手动操作时仍需注意

### 5. 首尾抽样回读（人工/AI）
- **做法**：抽查第 1 页、中间 1 页（如第 N/2 页）、最后 1 页，确认：
  - 无截断（开头结尾不缺字）
  - 无错位（多栏阅读顺序正确）
  - 表格结构正确（行列对齐、不串行）
  - 公式可读（LaTeX 格式正确或文字描述准确）
- **批量任务**：每 10 份抽 1 份做全量回读，其余做首尾抽样
- **AI 回读**：可用豆包多模态视觉对比源页图片和 OCR 文本，标注不一致处

## 二、校验工具用法

```bash
# 完整校验（含页数对账）
python3 scripts/verify_extract.py output.md --source input.pdf

# 只做文本质量检查（无页数对账）
python3 scripts/verify_extract.py output.md

# 批量校验
for f in out_dir/*.md; do
  src="src_dir/$(basename "$f" _extracted.md).pdf"
  python3 scripts/verify_extract.py "$f" --source "$src" 2>&1 | tail -5
done
```

退出码：0 通过，1 有问题。可在脚本中用 `$?` 判断。

## 三、不通过时的处理流程

```
校验不通过
  │
  ├─ 单页失败（缺页/空页/乱码）
  │   └─ 重跑该页（pdf_ocr.sh 断点续跑自动跳过已完成页，删对应 tmp txt 即可重跑）
  │
  ├─ 多页失败 / 整体残缺
  │   ├─ 检查转图环节（PyMuPDF DPI 是否够、PDF 是否加密/损坏）
  │   ├─ 检查 OCR 引擎（Vision 对该类内容是否合适）
  │   └─ 换引擎重跑：Vision → PP-StructureV3 → PaddleOCR-VL
  │
  ├─ 表格/公式页质量差
  │   └─ 该页单独用 PP-StructureV3 或 AI 视觉补充，合并回主稿
  │
  └─ 重复页/页码错乱
      └─ 清空 tmp 缓存，检查源 PDF 页码，从头重跑
```

## 四、校验结果记录

批量任务完成后，在任务报告中记录：
- 总文件数、通过数、不通过数
- 不通过文件清单及问题类型
- 处理方式（重跑/换引擎/人工修正）
- 最终交付文件的校验状态
